# 验证与调试策略

SFMC 默认不保留功能开发期间编写的临时测试脚本。完成实现后，清理临时脚本，并按改动范围选择类型检查、构建、平台自检和实际运行验收。不要把本地构建成功当作 BDS 或客户端验收成功。

## 模块作者

新建模块后，先运行静态检查：

```bash
pnpm run typecheck
pnpm run lint
```

随后通过扩展的 `SFMC: Link to SFMC Root` 和 `SFMC: Start Watch` 将模块同步到测试世界；使用 `SFMC: Reload to BDS` 或 `sfmc mod reload` 加载改动，并在 BDS 日志与客户端中检查实际行为。命令、权限、表单、方块与实体交互都应在真实运行环境中验收。

## 平台包

优先运行改动所在包的 `typecheck` 和 `build`。修改公共 SDK、安装器或发布行为时，再运行根目录 `pnpm run verify` 等相关集成自检。涉及 BDS 世界包或客户端资源时，确认源码、构建产物、部署包、服务端日志和客户端表现分别处于预期状态。

一次性验证命令可以用于排查问题；功能完成后不要留下未被产品运行链路使用的测试脚本。没有执行的运行验收需要在交付说明中明确标注。
