## 1. 为何蓝图（作者真实节奏）

测模块脚本时常见不是「只 Emit 一次」，而是：

1. 搭好一串刺激（进服感：玩家 → join → 聊天命令 → tick）  
2. **改一处**（命令文案、权限、顺序）  
3. **只重试这一步，或从某节点起重跑一条路径**——不必每次从零点完整个流程  

三区刺激台擅长单次填表；**蓝图擅长编排 + 局部重试 + 存盘复放**。本规格以蓝图为主壳。

| 项 | 内容 |
|----|------|
| 名称（UI） | **刺激剧本**（副标题可保留 Playground） |
| 一句话 | 用可连线的节点编排 SAPI 刺激，整图或局部重跑，日志里看模块反应 |
| 隐喻 | 轻量 Blueprint / 测试编排图；**不是**完整游戏逻辑可视化、不是真服事件总线 |
| 对照 | 模块冒烟「可点选重试的步骤图」；真机仍用 Watch |

---

## 2. 已锁定决策

| 决策 | 选择 |
|------|------|
| 主隐喻 | **刺激剧本（节点图）** |
| 单次 Emit | 保留为节点操作 / 「单步模式」，不作为唯一主路径 |
| 连线语义（MVP） | **控制流**（执行顺序 + 条件分支）；不做全量数据流端口 |
| Event 字段 | 选中 Emit 节点 → **侧栏表单**（`PLAYGROUND_META`）；不把每个字段拉成线 |
| 局部重试 | 一等公民：见 §4 |
| 场景实例 | World/Dim 天生；Player/Entity 由「场景节点」create 或图外实例坞 |
| UI 栈 | **React + xyflow + Radix**；皮跟 `--vscode-*`。Tailwind 已锁定意向，因仓库路径含 `#` 暂用手写等价 CSS，迁路径后再接 `@tailwindcss/cli` |
| 宿主 | 继续 `playground-host` JSON-RPC；图运行时 = 有序/分支调用 `objects.*` / `events.emit` / `tick` |
| 存盘 | 剧本 JSON（可进模块仓库）；格式见 §6 |

## 3. 信息架构

```text
┌─ 顶栏：运行整图 | 从选中运行 | 重置沙箱 | 保存/打开 ──────────┐
├────────────────────────────┬──────────────────────────────────┤
│ 画布（节点 + 控制流连线）     │ 侧栏：选中节点属性 / Event 表单     │
│                            ├──────────────────────────────────┤
│                            │ 视口：日志 | 状态 |（可选）运行轨迹 │
└────────────────────────────┴──────────────────────────────────┘
```

- **画布**：编排与选中  
- **侧栏**：1:1 字段（与旧刺激台属性区同源）  
- **视口**：系统日志 + 场景摘要；运行中高亮当前节点  

---

## 4. 运行与重试（核心体验）

### 4.1 运行范围

| 命令 | 行为 |
|------|------|
| **运行整图** | 从入口节点（或无入边节点集合按稳定序）走到结束 |
| **从选中运行** | 以当前节点为起点，沿出边跑子图（作者改完某步后最常用） |
| **仅运行选中** | 只执行当前一个节点（单步重试） |
| **运行到此处**（可后置） | 从入口跑到选中节点为止 |

### 4.2 沙箱与重试的关系

| 策略 | 何时 | 说明 |
|------|------|------|
| **保留世界** | 默认「仅运行选中 / 从选中运行」 | 玩家已在则不必再 create；适合调 payload |
| **重置再跑** | 「运行整图」可勾选；或顶栏「重置场景」 | 可复现全剧；避免脏状态 |
| 节点级「运行前重置」 | 后置 | 个别入口节点标记 |

失败时：**停在失败节点**（红态）+ 日志定位；不自动清空世界（除非策略要求）。

### 4.3 条件分支（MVP）

- **断言**节点：例如日志匹配正则 / 子串；真 → 走「通过」出边，假 → 「失败」出边或停住  
- 暂不做表达式语言；条件种类白名单扩展

## 5. 节点 MVP

| 节点 | 作用 | 侧栏 |
|------|------|------|
| **新建 Player** | `objects.create('Player', 预填袋)` | name / op / dim / location… |
| **Emit** | `events.emit(path, payload)` | 搜信号 + Event 表单 |
| **Tick** | `tick(n)` | n |
| **断言·日志** | 查最近日志 | 模式字符串；失败策略：停止 / 走失败边 |
| **注释** | 仅文档 | 文本 |

后置（非 MVP）：`objects.call`、等待事件、新建 Entity、表单应答、分组框。

**非目标节点：** 每个 SAPI 类一个方块、方块里拖满属性端口、模拟红石/物理。

---

## 6. 剧本文件（可复现）

- 路径约定（实现时定）：例如模块下 `stimulus/*.json` 或扩展工作区 `.sfmc/stimulus/*.json`  
- 内容至少包含：`schemaVersion`、`nodes[]`（id/type/position/data）、`edges[]`（source/target/kind）、可选 `viewport`  
- `data` 内嵌 Emit 的 `path` + `payload` 纯 JSON（与 RPC 一致；`$ref` 用实例 id 或「上一场景节点输出」的稳定 key）  
- CI / 本地：`playground-host` 或 CLI **无头重放**同 JSON（与 UI 共用执行器）——执行器与画布解耦（DIP）

---

## 7. 与 1:1 / 旧刺激台

| 能力 | 落点 |
|------|------|
| 全量 hub + Event 类型 | Emit 节点侧栏（meta 不变） |
| World / Dimension | 开沙箱即有；可只读展示在状态或「场景坞」 |
| 实验室 create/call/JSON | 后置 Call 节点或「单步实验室」页 |
| 三区大纲树 | 可保留为「场景坞」或单步模式，不与画布抢主路径 |

---

## 8. 技术要点

- 画布库：**@xyflow/react**（或 Preact 兼容方案）；扩展 Webview 打包  
- 执行器：纯 TS 模块（`runGraph(graph, range, hostClient)`），UI 与 CLI 共用  
- 开面板即沙箱（沿用）；重置与整图策略见 §4.2  
- CSP / `asWebviewUri` 按 VS Code 惯例；主题变量 `--vscode-*`

## 9. 分轮交付

| 轮次 | 交付 |
|------|------|
| **本轮 MVP** | 画布 + 五类节点 + 控制流边 + 整图/从选中/仅选中 + 侧栏表单 + 日志高亮失败节点 + 存盘 JSON |
| **下一轮** | 断言失败边、无头 CLI 重放、Entity 节点、轨迹回放 |
| **更后** | 数据口（player id → sender）、模块引导、启动并调试 |

---

## 10. 验收

1. 作者能搭：新建玩家 → Emit `chatSend` → Tick → 断言日志，**保存后再打开可跑出相同顺序**  
2. 改 Emit 文案后，用 **仅运行选中** 或 **从选中运行** 不必重搭前缀步骤  
3. 整图可选手重置沙箱后复现  
4. 不出现「85 个事件方块铺满画布」；信号仍在 Emit 内搜索  
5. 一句话可介绍：「IDE 里可局部重试的 SAPI 刺激剧本」

---

## 11. 规格自检（编写时）

- 无「以后再说」占运行范围：三种运行命令已列  
- 控制流 vs 数据流已划界  
- 与旧刺激台关系已写明，避免两套主隐喻并行无人管
