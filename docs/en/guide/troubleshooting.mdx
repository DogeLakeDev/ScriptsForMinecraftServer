# Troubleshooting & Diagnostics

When encountering server startup issues, inactive modules, or network errors, use the interactive troubleshooting wizard below for guided diagnosis. The complete checklist is also available below for search and fast reference.

## Comprehensive Troubleshooting Checklist

### 1. Port Conflicts & Networking (Port Conflicts)

| Conflicted Port | Service Involved | Typical Error / Symptom | Fix & Workaround |
| :--- | :--- | :--- | :--- |
| **`19132` (UDP)** | BDS Core Process | BDS fails to boot, crashes, or fails to bind port | Check for orphaned `bedrock_server` processes in the background; kill the PID via Task Manager / netstat. |
| **`3001` (TCP)** | db-server Data Daemon | Log outputs `EADDRINUSE :::3001` | Update `db_port` in `configs/db_config.json`, or override via `DB_PORT=3011` environment variable. |
| **`3002` (TCP)** | qq-bridge (LLBot WS) | LLBot connection rejected | Verify firewall rules allow the port, and ensure no duplicate bridge instances are running. |

```bash
# Windows inspect listening PID
netstat -ano | findstr 19132

# Linux / macOS inspect listening port
lsof -i :3001
```

---

### 2. Database Daemon (db-server) Issues

| Symptom | Root Cause | Action Steps |
| :--- | :--- | :--- |
| Exits immediately, `Cannot find module 'node:sqlite'` | Node.js version is too old | Upgrade Node.js to **`22.13.0` or higher** (the platform requires built-in SQLite support). |
| Write failures or `SQLITE_CORRUPT` | Disk errors or unclean power loss | Stop all services and restore the latest `.sqlite` database from `<SFMC_ROOT>/data/backups/`. |
| SAPI requests to data service return `401 Unauthorized` | Module token expired or invalid | Ensure SAPI's `ConfigManager.init()` successfully fetched snapshot configs, then run `mod reload`. |

```bash
# Test local db-server daemon health
curl http://127.0.0.1:3001/api/health
```

---

### 3. BDS Boot & Behavior Pack Assembly Gate

1. **Inspect Load Summary**: Review terminal load output and individual log files under `<SFMC_ROOT>/.sfmc/logs/`.
2. **Test Pack Bundling**: Execute `sfmc> mod build` to verify esbuild produces JavaScript bundles without TypeScript syntax errors.
3. **Check Add-on Conflicts**: Check `worlds/<level>/behavior_packs/` for duplicate or conflicting packs (see [Add-ons Guide](./addons.md)).

---

### 4. Module Enabled in Lock but Inactive In-Game

- **Update Boundaries**:
  - If you edited TypeScript code in `sapi/src/`: Run `sfmc> mod reload` to hot reload.
  - If you edited `configs/*.json` or `manifest.json`: You must **restart BDS**.
- **Lock Status**: Confirm that `enabled: true` is set for this module in `<SFMC_ROOT>/modules/module-lock.json`.
- **Lifecycle Ordering**: If entity/dimension operations fail during module boot, verify if `ModuleRegistry.register` should specify `afterWorldLoad: true`.
- **Dependencies**: Check that all modules listed under `dependencies` in `manifest.json` are installed and enabled.

---

### 5. QQ Bridge & Bot Connection Issues

:::tabs
== Official OpenAPI Backend (`official`)
1. **Credentials**: Check `qq_app_id` and `qq_app_secret` in `configs/qq_config.json`.
2. **IP Allowlist**: In the QQ Open Platform developer console, ensure your server's public IP is added to the IP allowlist.
3. **Event Subscription**: Ensure `GROUP_AT_MESSAGE_CREATE` is subscribed (messages in groups must @ the bot).
4. **Group OpenID**: Copy the generated `qq_group_openid` from initial trigger logs into `configs/qq_config.json`, then restart services.

== LLBot / OneBot Backend (`llbot`)
1. **Reverse WebSocket**: Confirm reverse WS target in LLBot is set to `ws://127.0.0.1:3002`.
2. **Group Number**: Ensure `qq_group_id` in `configs/qq_config.json` is a valid numeric group ID.
3. **Firewall**: Confirm port 3002 is not blocked by local security software.
:::

### 6. Test Sandbox FAQs

```bash
pnpm test
npm test
# Note: Tests must import the Minecraft runtime mock loader:
# --import @sfmc-bds/sdk/testing/minecraft-loader
```

| Symptom | Details & Solution |
| :--- | :--- |
| `UnimplementedMinecraftApiError` | Test touched an obscure Minecraft SAPI not yet mocked in the sandbox. Narrow test assertions or verify with live BDS; not a business logic flaw. |
| Assertion fails but works in live BDS | Sandbox fidelity difference; use VS Code extension Watch mode in a real BDS instance for debugging. |

---

### 7. Reporting Issues & Help

If the issue persists after following these steps, please open an issue at [GitHub Issues](https://github.com/Tanya7z/sfmc-modules/issues) and include:
- Complete terminal log output (or `.sfmc/logs/` archive)
- `pnpm run verify` output
- `node -v` and Operating System details
