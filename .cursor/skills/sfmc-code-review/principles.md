# SFMC 审查原则

日常以 `SKILL.md` 速记为准；此处补充期望形态与修法。

## DRY

同一规则一处权威来源。鉴权、lock/catalog、默认配置抽共享实现；调用方引用，不平行拷贝。

## OCP

新能力通过注册、路由工厂、策略表扩展现有表面。

## DIP

模块与脚本走 `@sfmc-bds/sdk` 公开面。能力在可独立调用的服务包内；CLI 负责编排。

## LSP

可互换路径遵守同一契约：单操作与 `/db/tx`、HTTP service 与 `tx.call` 在 moduleId、权限门、结果信封上对齐；用共享校验与测试钉住。

## 迪米特（最少知识）

模块经 manifest 声明的 service / 公开 SDK API 协作。路由只依赖文档化的请求字段；包与包之间用公开 export。

## 合并判断

- 原则债可标 MAJOR（即使当前能跑）。
- BLOCKER 优先：安全、鉴权旁路、跨模块数据串扰、发布契约。
- 修复时保留仍正确的既有行为。
